= Build a LAMP Development Container

== Introduction

**Image Mode for RHEL** is a container-native way to deploy Red Hat Enterprise Linux. Instead of installing packages on a running system, you build the entire OS as a bootable container image. This bridges the gap between development teams (who love containers) and operations teams (who need reliable OS deployments).

This two-lab series teaches **application developers** how to use Image Mode. Most Image Mode labs focus on platform engineering - OS configuration, compliance, updates. This lab focuses on **packaging your application** for deployment.

**The scenario:** You've built a web application (a database-backed LAMP stack). Now you need to deploy it. Lab 1 teaches the development workflow with fast iteration. Lab 2 teaches production packaging as a bootable image.

*Time: ~28 minutes | Difficulty: Beginner*

== What You'll Build

A database-backed web application using the **LAMP stack**:

**LAMP** = **L**inux + **A**pache + **M**ariaDB + **P**HP

- **Linux**: The operating system (RHEL, running in a container)
- **Apache**: Web server that handles HTTP requests and serves your web pages
- **MariaDB**: Database server that stores and retrieves your application data
- **PHP**: Programming language that connects to the database and generates dynamic web pages

This is a classic web application stack used by millions of websites.

== The Development Workflow

You'll use **volume mounts** - a container feature that makes files on your host computer instantly available inside the container.

**Why this matters:** Edit `index.php` on your laptop → change appears immediately in the running container → no rebuild, no restart. This makes development fast and interactive.

**The trade-off:** Volume mounts are great for development but problematic for production (files can be modified, no version control). Lab 2 shows the production approach: baking files into the image at build time.

== Key Concepts You'll Use

**Container**: Isolated environment that runs your application with all its dependencies. Like a lightweight virtual machine, but faster.

**Volume mount**: Shares a directory from your computer into the container. Files on your host = files in container, instantly.

**Systemd**: Linux service manager. Starts services like MariaDB and Apache when the container boots.

**Bootable container** (Lab 2): A container image that can boot as a complete operating system, not just run an application.

== What You'll Learn

- Understanding when to use mutable (dev) vs immutable (production) workflows
