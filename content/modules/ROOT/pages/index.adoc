= Lab 1 of 2: Build a LAMP Development Container

== Welcome to Lab 1!

Welcome! You're in the right place. In this lab you'll build a real database-backed LAMP application and learn the fast development workflow that Image Mode is built for.

This is **Lab 1 of 2** for application developers. Lab 1 is hands-on and beginner-friendly. When you finish, you'll be ready for Lab 2, where you package the *same* app as a bootable production image.

.Lab series roadmap

**In this lab (Part 1):** Build the app and iterate quickly with volume mounts: edit on the host, see changes instantly.

**In Lab 2 (Part 2):** Package that same application as an immutable bootable image (`zt-image-mode-lamp-02-bootable`).

**Image Mode for RHEL** is a container-native way to deploy Red Hat Enterprise Linux. Instead of installing packages on a running system, you build the entire OS as a bootable container image. That bridges development teams (who work in containers) and operations teams (who need reliable OS deployments). Most Image Mode labs target platform engineers. This series focuses on **packaging your application**.

== What You'll Build

A database-backed web application using the **LAMP** stack (**L**inux + **A**pache + **M**ariaDB + **P**HP):

- **Linux**: RHEL running in a container
- **Apache**: serves HTTP requests
- **MariaDB**: stores application data
- **PHP**: queries the database and renders HTML

== The Development Workflow

**Volume mounts** make files on your host available inside the container instantly.

.Volume mounts: edit on the host, appear in the container
image::volume-mount-diagram.svg[Host lamp-dev app directory mounted to container /app,width=1000]

**Why it matters:** Edit `index.php` on the host → refresh the browser → no rebuild, no restart.

**Trade-off:** Great for development; not ideal for production (mutable files, no baked-in version). Lab 2 shows the production approach: `COPY` files into the image at build time.

== Who This Lab Is For

**Most Image Mode labs teach:** OS policies, monitoring, updates (for platform engineers).

**This lab teaches:** packaging a real web app, writing SQL/PHP/Apache config, and the mutable (dev) vs immutable (prod) workflow (for application developers).

== Key Concepts

- **Container**: isolated environment with your app and dependencies
- **Volume mount**: host directory shared into the container (`~/lamp-dev/app` → `/app`)
- **Systemd**: starts MariaDB and Apache inside the container
- **Bootable container** (Lab 2): an image that boots as a full OS, not just an app process

== What You'll Learn

- Build a systemd-enabled LAMP container
- Use volume mounts for fast iteration
- Create a database schema and PHP app
- Configure Apache to serve the app
- Know when mutable (dev) vs immutable (prod) workflows apply
