= Test and Iterate on Your Application

Your LAMP application works, but you discovered edits don't appear. In this module, you'll fix the workflow and experience true iterative development.

**What "iterate" means:** Make changes → see results immediately → make more changes. No waiting for rebuilds or restarts.

In this module, you'll:
- Fix Apache to serve from the volume mount
- Verify your heading change from Module 2 appears
- Add new database content and PHP code
- See all changes appear instantly

This is why developers love volume mounts for development.

*Time: ~7 minutes*

== Fix the Workflow

In Module 2, you edited `index.php` but the heading didn't change. Here's why:

**The problem:**
- Apache is serving from `/var/www/html` (where you copied the file)
- Your volume mount is at `/app` (where you're editing)
- Editing `/app/index.php` doesn't affect what Apache serves

**The solution:** Reconfigure Apache to serve directly from the volume mount.

Enter the container:

[source,bash,role=execute]
----
podman exec -it lamp-dev-container bash
----

Edit the Apache configuration:

[source,bash,role=execute]
----
sed -i 's|DocumentRoot /var/www/html|DocumentRoot /app|' /etc/httpd/conf.d/myapp.conf
----

Also update the Directory directive:

[source,bash,role=execute]
----
sed -i 's|<Directory /var/www/html>|<Directory /app>|' /etc/httpd/conf.d/myapp.conf
----

Reload Apache to apply changes:

[source,bash,role=execute]
----
systemctl reload httpd
----

Exit the container:

[source,bash,role=execute]
----
exit
----

Now refresh the **LAMP Application** browser tab.

**Success!** The heading now shows "My LAMP Application" - your edit from Module 2 finally appears. Apache is now serving directly from `/app`, which is your volume mount.

== Add New Content and See It Instantly

Now that Apache serves from the volume mount, let's prove iterative development works. You'll add database content and modify the PHP code - both changes will appear immediately.

First, add a new database message. Enter the container:

[source,bash,role=execute]
----
podman exec -it lamp-dev-container bash
----

Insert a new message:

[source,bash,role=execute]
----
mariadb -u hellouser -pSecurePassword hellodb -e "INSERT INTO greetings (message) VALUES ('Iteration is instant');"
----

Query the table to verify:

[source,bash,role=execute]
----
mariadb -u hellouser -pSecurePassword hellodb -e "SELECT * FROM greetings;"
----

*Expected output (4 rows now):*

----
+----+------------------------------------+---------------------+
| id | message                            | created_at          |
+----+------------------------------------+---------------------+
|  1 | Hello, World!                      | 2026-10-13 19:06:17 |
|  2 | Welcome to LAMP development!       | 2026-10-13 19:06:17 |
|  3 | Volume mounts make iteration fast. | 2026-10-13 19:06:17 |
|  4 | Iteration is instant               | 2026-10-13 19:08:42 |
+----+------------------------------------+---------------------+
----

[NOTE]
====
The timestamps will show your actual current time, not the dates above.
====

Exit the container:

[source,bash,role=execute]
----
exit
----

Refresh the **LAMP Application** tab. The new message appears immediately - no restart needed.

Now add visual changes to the PHP file. Edit on your host:

[source,bash,role=execute]
----
cat >> ~/lamp-dev/app/index.php << 'EOF'

<!-- Modified during development -->
<div style="background: #fff3cd; padding: 10px; margin-top: 20px; border-radius: 5px;">
    <strong>Note:</strong> This application uses volume mounts for development.
    Changes to this file appear instantly without rebuilding the container.
</div>
EOF
----

This appends a yellow note box to the bottom of your page.

No rebuild. No restart. Just refresh the **LAMP Application** tab.

**The yellow box appears immediately!** Because Apache now serves from `/app` (the volume mount), your host file edits appear instantly inside the container.

This is the mutable workflow - perfect for development, but not for production.

== Understand What You Built

You've created a development environment where:
- **Files live on your host** (`~/lamp-dev/app/`)
- **Volume mounts make them available inside the container** (`/app/`)
- **Apache serves directly from the mount**
- **Edits appear instantly**

This is fast, flexible, and great for development. But it has problems for production:
- Files are mutable (someone could SSH in and edit them)
- No versioning (what version is deployed?)
- No reproducibility (every container could be different)

In Lab 2, you'll transform this into an immutable production deployment - files baked into the image, packaged as a bootable VM.

== Stop the Development Container

Stop and remove the container:

[source,bash,role=execute]
----
podman stop lamp-dev-container
podman rm lamp-dev-container
----

Your application files remain on your host at `~/lamp-dev/app/`. You can rebuild the container anytime with the same files.

[TIP]
====
*Development workflow summary:*

1. Volume mounts (`-v ~/lamp-dev/app:/app:z`)
2. Mutable files (edit anytime, changes appear instantly)
3. Fast iteration (no rebuild needed)
4. Perfect for development

*What's next:*

Lab 2 teaches the production workflow:
- COPY directives (files baked into image at build time)
- Immutable deployments (can't edit files after build)
- Bootable images (entire OS + application packaged as one)
====
