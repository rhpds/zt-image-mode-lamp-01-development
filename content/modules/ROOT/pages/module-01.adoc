= Prepare Your Development Environment

*Lab 1 of 2, Module 1*

Before building an application, you need a base container image. Think of this as the foundation: Red Hat Enterprise Linux with a LAMP stack (MariaDB, Apache, PHP) already installed.

**What you'll do:**
1. Verify you can access Red Hat's container registry (where base images live)
2. Check that the base image is available
3. Review a Containerfile (like a recipe for building the container)
4. Build your LAMP development container

This container will have the services installed but no application yet. You'll add your application in Module 2.

== Verify Registry Authentication

Your environment is pre-authenticated to Red Hat's container registry. Verify the authentication is working:

[source,bash,role=execute]
----
podman login registry.redhat.io
----

*Expected output:*

----
Authenticating with existing credentials for registry.redhat.io
Existing credentials are valid. Already logged in to registry.redhat.io
----

This shows you're already authenticated. The environment uses a pre-configured authentication, so you don't need to enter credentials manually.

== Verify Base Image is Available

The UBI (Universal Base Image) was pre-pulled during setup. Verify it's ready:

[source,bash,role=execute]
----
podman images
----

*Expected output (look for ubi-init):*

----
REPOSITORY                           TAG      IMAGE ID      CREATED      SIZE
registry.redhat.io/ubi10/ubi-init    latest   <image-id>    <date>       <size>
----

[NOTE]
====
The IMAGE ID, CREATED date, and SIZE will vary. Look for the `registry.redhat.io/ubi10/ubi-init` repository name.
====

This base image includes systemd support, which lets you run services (MariaDB, Apache) inside containers just like on a regular RHEL host.

== Review Your Workspace

Your development directory structure is already set up. Check what's available:

[source,bash,role=execute]
----
cd ~/lamp-dev
ls -la
----

*Look for:* `Containerfile`, `README.md`, and an `app/` directory.

- `app/` - application files you will create (SQL, PHP, Apache config)
- `README.md` - quick reference

Unlike OS-focused Image Mode labs, you're building an actual application. The `app/` directory holds code, not just OS configuration.

== Review the Development Containerfile

A Containerfile is already provided. Review it:

[source,bash,role=execute]
----
cat Containerfile
----

*Expected output:*

[source,dockerfile]
----
# Development LAMP Stack Container
# Uses UBI for development with volume mounts
FROM registry.redhat.io/ubi10/ubi-init:latest

# Install LAMP stack
RUN dnf install -y mariadb-server httpd php php-mysqlnd && \
    dnf clean all

# Enable services
RUN systemctl enable mariadb httpd

# Expose Apache port
EXPOSE 80

# Use systemd as init
CMD ["/sbin/init"]
----

This does three things:
1. Starts from a RHEL base image with systemd support
2. Installs MariaDB, Apache, and PHP
3. Enables services to start when the container boots

Notice what's *not* here - no application files. You'll add those using volume mounts (next module).

== Build the Development Container

Build the container image:

[source,bash,role=execute]
----
podman build -t lamp-dev .
----

You'll see installation steps as packages are installed. Give it a moment to finish.

Once complete, verify the image exists:

[source,bash,role=execute]
----
podman images lamp-dev
----

*Expected output:*

----
REPOSITORY          TAG         IMAGE ID      CREATED         SIZE
localhost/lamp-dev  latest      107092991f49  14 seconds ago  487 MB
----

[NOTE]
====
The IMAGE ID, CREATED time, and SIZE will vary based on when you built the image and current package versions.
====

You now have a base LAMP container. Next module: add your application and start the services.
