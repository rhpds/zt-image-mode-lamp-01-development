= Prepare Your Development Environment

Most Image Mode labs focus on platform engineering - building OS images with monitoring tools and compliance baselines. This lab focuses on application development - packaging a database-backed LAMP application from development to production.

You'll build a development container for your LAMP application using volume mounts for fast iteration.

*Time: ~6 minutes*

== Verify Registry Authentication

Your environment is pre-authenticated to Red Hat's container registry. Verify the authentication is working:

[source,bash,role=execute]
----
podman login registry.redhat.io
----

*Expected output:*

----
Authenticating with existing credentials for registry.redhat.io
Existing credentials are valid. Already logged in to registry.redhat.io
----

This shows you're already authenticated. The environment uses a pre-configured token, so you don't need to enter credentials manually.

Check the authentication file:

[source,bash,role=execute]
----
cat ~/.config/containers/auth.json | jq
----

*Expected output:*

[source,json]
----
{
  "auths": {
    "registry.redhat.io": {
      "auth": "..."
    }
  }
}
----

This file stores your authentication token for `registry.redhat.io`.

== Verify Base Image is Available

The UBI (Universal Base Image) was pre-pulled during setup. Verify it's ready:

[source,bash,role=execute]
----
podman images | grep ubi-init
----

*Expected output:*

----
registry.redhat.io/ubi10/ubi-init   latest   ...   ...   ...
----

This base image includes systemd support, which lets you run services (MariaDB, Apache) inside containers just like on a regular RHEL host.

== Review Your Workspace

Your development directory structure is already set up. Check what's available:

[source,bash,role=execute]
----
cd ~/lamp-dev
ls -la
----

*Expected output:*

----
total ...
drwxr-xr-x.  3 rhel rhel   ... .
drwx------. 14 rhel rhel   ... ..
drwxr-xr-x.  2 rhel rhel   ... app
-rw-r--r--.  1 rhel rhel   ... Containerfile
-rw-r--r--.  1 rhel rhel   ... README.md
----

This workspace holds:
- `Containerfile` - defines your LAMP container
- `app/` - your application files (SQL, PHP, Apache config)
- `README.md` - quick reference guide

Unlike OS-focused Image Mode labs where you install monitoring tools, you're building an actual application. The `app/` directory will contain code you write, not just configuration.

== Review the Development Containerfile

A Containerfile is already provided. Review it:

[source,bash,role=execute]
----
cat Containerfile
----

*Expected output:*

[source,dockerfile]
----
FROM registry.redhat.io/ubi10/ubi-init

# Install LAMP stack
RUN dnf install -y mariadb-server httpd php php-mysqlnd && dnf clean all

# Enable services
RUN systemctl enable mariadb httpd

# Expose web port
EXPOSE 80

CMD ["/usr/sbin/init"]
----

This does three things:
1. Starts from a RHEL base image with systemd support
2. Installs MariaDB, Apache, and PHP
3. Enables services to start when the container boots

Notice what's *not* here - no application files. You'll add those using volume mounts (next module).

== Build the Development Container

Build the container image:

[source,bash,role=execute]
----
podman build -t lamp-dev .
----

You'll see installation steps as packages are installed. This takes ~2 minutes.

Once complete, verify the image exists:

[source,bash,role=execute]
----
podman images lamp-dev
----

*Expected output:*

----
REPOSITORY          TAG         IMAGE ID      CREATED         SIZE
localhost/lamp-dev  latest      a1b2c3d4e5f6  2 minutes ago   850 MB
----

You now have a base LAMP container. Next module: add your application and start the services.
